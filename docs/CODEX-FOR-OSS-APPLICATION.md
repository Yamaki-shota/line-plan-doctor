# Codex for Open Source 応募メモ

応募対象は `line-plan-doctor` を推奨します。

## 何のOSSか

LINE/Lステップ案件資料の抜け漏れを診断するCLIです。Markdownの設計資料を読み、目的、対象者、タグ、友だち情報欄、シナリオ、分岐、リッチメニュー、フォーム、公開前QA、担当、完了条件の不足を検出します。

## なぜ自分が作るか

小規模店舗向けLINEマーケティング案件では、非エンジニアが設計、文面、フォーム、タグ、QAをまとめて扱います。自分自身の案件運用でも、公開直前の抜け漏れを減らすチェックが必要です。だから、自分の実務に使いながら保守できます。

## 応募フォーム記入案

### あなたの役割

メインメンテナー

### このリポジトリが対象となる理由

LINE Plan Doctorは、小規模店舗向けLINE/Lステップ案件の設計抜けを診断するOSS CLIです。スター数はまだありませんが、自分の実務で使う明確な保守理由があります。非エンジニアでも、案件資料をMarkdownで書いて実行するだけで、タグ、友だち情報欄、シナリオ、分岐、フォーム、公開前QA、完了条件の不足を確認できます。LINE運用の事故を減らす、地味ですが実用的な開発者向けツールです。

### 興味のある項目

- Codex Security
- プロジェクトで使用するAPIクレジット

### APIクレジットをどのように活用する予定か

APIクレジットは、チェックルールの追加、Issue/PRの要約、サンプル案件資料の匿名化、ドキュメント改善、誤検知レビュー、GitHub Actions連携の設計に使います。将来的には、診断結果からCodex向けの修正指示を生成し、案件資料の抜け漏れ修正を安全に進めるワークフローを作ります。

### 他に伝えたいこと

このOSSは、大きなSaaSを作るものではありません。小規模店舗のLINE導線づくりで、非エンジニアが毎回つまずく設計チェックを機械化する小さな道具です。自分の実案件で使いながら、個別顧客情報を入れずに汎用ルールとして育てます。

## 応募前チェック

- GitHubに新規リポジトリを作る
- README、LICENSE、CONTRIBUTING、SECURITYを入れる
- 最初のIssueを3つ作る
- `npm test` が通る状態でpushする
- 応募フォームには、このメモの文章を短くして貼る
